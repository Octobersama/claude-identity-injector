# 插件全库代码审查整改计划

> 基线：`master` / `3403de7`（已推送到 `origin/master`）
>
> 本文记录严格代码审查发现、拟议整改顺序和需要产品决策的事项。当前只写计划，未实施整改。

## 1. 目标与范围

本轮目标是保持已经验证的 OpenCode -> AnyRouter 兼容行为，同时修复设置页配置丢失、统计口径错误、资源筛选不完整和严格模式结构复杂度问题。

范围仅限插件仓库：

- `web/settings.html`：设置页状态、条件 Tab 和保存逻辑；
- `interceptor.go` / `management.go`：请求计数和状态展示；
- `strict_profile.go`：严格模式档位建模与执行流程；
- `response_normalizer.go` / `tool_arguments.go` / `main.go`：不可达响应规整代码的处置；
- 对应单元测试、竞态测试、文档和迁移说明。

本轮不修改 CPA 本体，除非后续确认插件 ABI 确实缺少实现所需能力，并在实施前单独说明原因和影响。

## 2. 已确认问题

### P1：设置页保存会清空请求模型条件

位置：`web/settings.html:847`、`web/settings.html:891`。

连接和保存时都把 `match_requested_models` 设为 `false`、`requested_models` 设为空。旧配置只要被设置页打开并保存一次，请求模型规则就会丢失。

拟议修复：

1. 读取配置时保留 `match_requested_models` 和 `requested_models`；
2. 保存时原样保留未知/暂不编辑的规则字段；
3. 如果设置页不继续提供请求模型编辑，显示“此字段由配置文件保留，当前页面不修改”；
4. 增加回归测试：加载带请求模型条件的配置，模拟保存后字段必须完全不变。

### P1：条件 Tab 切换会丢失其他 Tab 的选择

位置：`web/settings.html:631-645`、`web/settings.html:687-691`。

当前 DOM 只渲染一个 Tab 的选项；勾选时从当前 DOM 汇总并覆盖整个字段。因此跨 Tab 选择多个提供商/认证文件时，后一次操作会清掉前一个 Tab 的选择。

拟议修复：

- 方案 A（首选）：继续只渲染当前 Tab，但更新时以 `rule[key]` 为基准，先删除当前分组值，再合并当前分组的新选择；
- 方案 B：一次渲染全部选项，用 CSS 隐藏非当前 Tab，事件处理始终读取全部 checkbox；
- 增加跨 Tab 选择、切换、保存、重新加载的浏览器回归步骤。

### P1：请求计数按两个拦截阶段重复累计

位置：`interceptor.go:71-94`、`management.go:133-159`。

同一个请求会经过 `pre_cloak` 和 `final` 两次。`seen` 在两个阶段都增加，`matched` 主要在最终阶段增加，面板使用 `seen - matched` 推导 `unmatched`，会产生虚假的未匹配请求。

拟议修复：

- 以非空 `RequestID` 为请求去重键，只有首次进入规则检查时增加 `seen`；
- 对缺少 `RequestID` 的管理探针使用短生命周期去重策略，或明确标注为“阶段调用”而不纳入请求计数；
- `matched`、`injected`、`already_present`、`errors` 统一按请求维度统计；
- 把 `unmatched` 作为独立计数或基于同一去重集合计算，禁止用不同维度的两个计数直接相减；
- 增加 pre-cloak/final 双阶段、重试未命中、并发请求和缺失 RequestID 测试。

### P1/P2：已配置密钥的筛选错误依赖模型列表

位置：`web/settings.html:647-655`。

“已配置密钥”目前要求 `source === 'config'` 且 `models.length > 0`。模型列表暂时为空时，活跃密钥会被错误隐藏。

拟议修复：

- 以 `source === 'config'`、未禁用、未不可用和有效 `auth_index` 作为密钥条目可选条件；
- `models` 只用于状态提示，不作为条目存在与否的门槛；
- 增加“活跃但暂无模型”“禁用”“不可用”“非 config Auth 文件”的筛选测试。

### P2：严格档位由布尔组合驱动，存在组合爆炸

位置：`strict_profile.go:52-70`、`strict_profile.go:77-210`、`strict_profile.go:213-268`。

多个正交布尔值共同描述 profile，执行流程在多个位置判断这些布尔值。新增档位容易引入互相矛盾的组合，读者必须同时理解 profile 名称、控制字段和执行顺序。

拟议修复：

1. 将 profile 解析为显式策略（例如 `minimum`、`legacy`/`full` 等策略对象）；
2. 每个策略负责声明 body、headers、tools、auth 选择和上游 transform 行为；
3. 把共用的身份、metadata、system 搬移和工具处理拆为纯函数；
4. 保留旧 profile 名称作为兼容别名，避免已有配置失效；
5. 以行为矩阵测试替代大量布尔字段断言。

### P2：响应规整入口在当前 ABI 分发中不可达

位置：`response_normalizer.go:23-73`、`tool_arguments.go:26-51`、`main.go:134-149`。

仓库保留了 `response.normalize_*` 风格的旧入口和测试，但 `handleMethod` 没有分发这些方法，注册能力也没有声明。实际生产路径是 `response.intercept_after` 和 `response.intercept_stream_chunk`。

拟议修复：

- 删除不可达入口及仅覆盖该入口的重复测试；
- 或在确认当前 CPA ABI 有对应能力后完整接回，但不得同时保留两套会修改相同响应的路径；
- 在测试中增加“生产分发方法可达性”检查，防止测试覆盖不可调用代码。

## 3. 实施顺序

### 阶段 A：先修复数据安全和统计正确性

1. 保留请求模型条件和未知规则字段；
2. 修复跨 Tab 选择合并；
3. 重新设计请求维度计数；
4. 修复已配置密钥筛选；
5. 补充单元测试和面板手工验证。

### 阶段 B：整理严格模式结构

1. 先冻结现有 `minimum` 行为快照；
2. 抽取 profile 策略边界；
3. 保留兼容别名并逐档位跑回归测试；
4. 跑 `go test ./...`、`go test -race ./...`、`go vet ./...` 和插件构建脚本。

### 阶段 C：清理不可达代码

1. 根据决策删除或接回响应规整入口；
2. 检查注册能力、方法分发和文档是否一致；
3. 再跑全量测试并进行一次 OpenCode AnyRouter 端到端工具回归。

## 4. 验收标准

- 设置页打开并保存不会改变未编辑的请求模型条件或其他规则字段；
- 同一条件跨多个 Tab 选择后，切换 Tab、重新渲染和重新加载仍保留全部选择；
- 一条请求只计入一次 `seen`、`matched` 和最终 outcome；`unmatched` 不再因 pre-cloak/final 双阶段虚增；
- 所有已配置且启用的密钥均可选择，即使当前没有模型列表；禁用/不可用条目不可选择；
- `minimum` 严格模式的请求体、请求头、工具 Schema 和响应修复行为与当前生产快照一致；
- 生产分发路径不再存在不可达的重复响应处理实现；
- 全量 Go 测试、竞态测试、vet、构建脚本和 OpenCode 工具回归均通过。

## 5. 需要用户决策

### 决策 1：请求模型条件如何处理

- **A（推荐）**：继续保留并在设置页重新提供“请求模型”条件；
- **B**：设置页不编辑，但完整保留配置并显示只读提示；
- **C**：正式废弃该条件，保存时迁移删除，并在文档中明确说明。

### 决策 2：统计口径

- **A（推荐）**：面板所有主要计数按“唯一请求”统计；另加一个仅供诊断的“拦截调用次数”；
- **B**：保留当前阶段调用口径，但将字段重命名为 `intercept_calls`，不再显示“请求”字样。

### 决策 3：不可达响应规整代码

- **A（推荐）**：删除不可达入口和重复测试，只保留当前实际的响应拦截链；
- **B**：确认并扩展 CPA ABI 后接回入口，同时补齐注册能力和生产调用链。

### 决策 4：严格 profile 重构范围

- **A（推荐）**：只重构内部表示，保持所有现有 profile 名称和行为；
- **B**：同时合并/淘汰实验档位，接受配置迁移和兼容性变更。

## 6. 当前建议

在未收到决策前，可以直接实施阶段 A 的前三项安全修复，但不会删除请求模型条件、不可达代码，也不会合并 profile。阶段 B/C 等待对应决策后执行。
